The Machine Learning Landscape

Taxonomy of Supervised vs. Unsupervised learning paradigms.

Supervised Learning (Labeled Data: X, y)

  • Goal: Learn a mapping f(X) → y from known input-output pairs.
  • Regression: Continuous targets (house price, demand, temperature). Models: Linear, Polynomial, Ridge, Lasso, Trees, GBDT.
  • Classification: Discrete class labels (spam/ham, diagnosis). Models: Logistic, k-NN, Naive Bayes, SVM, Trees, Forests, GBDT.

Unsupervised Learning (Unlabeled Data: X)

  • Goal: Discover hidden structure, groupings, or compact representations without labels.
  • Clustering: Group similar observations (K-Means centroids) or dense regions with outlier detection (DBSCAN).
  • Dimensionality Reduction: Project high-dimensional features onto orthogonal axes of maximum variance (PCA).

The End-to-End ML Workflow

Splitting data, preventing leakage with Pipelines, and evaluating on unseen test sets.

Further Visuals & Docs: Kaggle Intermediate ML

Core Pipeline Principles

  • Train/Test Split: Hold out 20% of data before any preprocessing to get an honest generalization score.
  • Data Leakage Prevention: Fit scalers/imputers ONLY on training data; apply the learned transform to test data.

Why Pipelines Matter

  • Reproducibility: Bundles preprocessing + model into one atomic object.
  • Cross-Validation: Ensures scaling happens freshly inside each CV fold.

Bias-Variance Trade-off: Underfitting vs. Overfitting

Balancing model complexity so predictions generalize to new, unseen data.

Further Visuals & Docs: ISLR / ISLP Textbook

Diagnosing Model Fit

  • High Bias (Underfitting): Model is too rigid (e.g., straight line on curved data); both train and test errors are high.
  • High Variance (Overfitting): Model memorizes training noise; train error is near 0% but test error spikes.

How to Find the Sweet Spot

  • Validation Curves: Use k-fold cross-validation to track validation error as complexity grows.
  • Remedies: Add regularization or more data to fix variance; add features/flexibility to fix bias.

Linear Regression (Ordinary Least Squares)

Fitting a hyperplane by minimizing the sum of squared vertical residuals.

Further Visuals & Docs: Scikit-Learn Linear Models

Architecture & Math Intuition

  • Equation: y_hat = w1*x1 + w2*x2 + ... + b.
  • Objective (MSE): Minimizes (1/n) * sum((y_i - y_hat_i)^2) via closed-form normal equation or SVD.

When to Use & Trade-offs

  • Strengths: Fast, zero hyperparameters, directly interpretable feature weights (w_j).
  • Limitations: Sensitive to outliers (squared error) and struggles with collinearity or curves.
SUPERVISED: REGRESSION6 / 22

Polynomial Regression (Basis Expansion)

Capturing non-linear curves while still using a fast linear solver.

Further Visuals & Docs: Scikit-Learn Linear Models

Architecture & Intuition

  • Feature Expansion: Transforms input x into [x, x^2, ..., x^d] and interaction terms x1*x2.
  • Linear in Weights: Still solved by OLS because the weights w remain linear!

When to Use & Trade-offs

  • Degree d: d=2 or 3 captures smooth curves; high d explodes feature count and overfits.
  • Best Practice: Pair with Ridge/Lasso regularization and feature scaling.
SUPERVISED: REGULARIZATION7 / 22

Ridge (L2) vs. Lasso (L1) Regression

Constraining weight magnitude to tame overfitting and perform feature selection.

Further Visuals & Docs: StatQuest: Ridge vs. Lasso Scikit-Learn Linear Models

Constraint Geometry & Sparsity

  • Ridge (L2): Adds alpha * sum(w_j^2). Circular constraint shrinks correlated weights smoothly toward zero.
  • Lasso (L1): Adds alpha * sum(|w_j|). Diamond corners hit axes, setting irrelevant weights to exact 0.

Choosing Between L1 & L2

  • Use Ridge: When most features carry useful signal or are correlated.
  • Use Lasso: When you want automatic feature selection (sparse model). Always scale features first!

Logistic Regression

Mapping a linear combination through the Sigmoid function for probability estimates.

Further Visuals & Docs: Scikit-Learn Classifier Comparison

Architecture & Objective

  • Sigmoid Activation: sigma(z) = 1 / (1 + e^-z) squashes any real score z = w^T x + b into (0, 1).
  • Loss Function: Minimizes Binary Cross-Entropy (Log Loss) rather than MSE.

When to Use & Trade-offs

  • Decision Boundary: Linear hyperplane where P(y=1|x) = 0.5 (threshold can be tuned for precision/recall).
  • Strengths: Fast, interpretable log-odds, and outputs probability estimates (check calibration if probabilities matter).
SUPERVISED: CLASSIFICATION9 / 22

k-Nearest Neighbors (k-NN)

Non-parametric, instance-based classification by local neighborhood voting.

Further Visuals & Docs: Scikit-Learn Classifier Comparison

Architecture & Intuition

  • Lazy Learner: Zero training optimization — stores training points and measures distances at query time.
  • Choosing k: Small k (e.g. 1) overfits noise; larger k smooths the decision boundary.

When to Use & Trade-offs

  • Scaling Crucial: Unscaled features with large ranges dominate Euclidean distance.
  • Curse of Dimensionality: Slows down and loses accuracy when feature count is very high.
SUPERVISED: CLASSIFICATION10 / 22

Naive Bayes Classifier

Fast probabilistic classification via Bayes' Theorem and conditional independence.

Further Visuals & Docs: 3Blue1Brown: Bayes Theorem

Architecture & Variants

  • Bayes Rule: P(y | X) proportional to P(y) * product(P(x_i | y)).
  • 'Naive' Assumption: Assumes features are independent given the class — works surprisingly well in practice!

Common Variants & Use Cases

  • Variants: GaussianNB (continuous features), MultinomialNB (word counts / NLP), BernoulliNB (binary).
  • Strengths: Blazing fast training, handles high-dimensional text/spam filtering effortlessly.
SUPERVISED: CLASSIFICATION11 / 22

Support Vector Machines (SVM): Linear Margin

Finding the widest separating street (maximum margin) between classes.

Further Visuals & Docs: StatQuest: SVMs Playlist

Support Vectors & Margin

  • Maximum Margin: Maximizes 2 / ||w|| so the boundary stays as far from both classes as possible.
  • Support Vectors: Only the closest edge points (red rings) define the hyperplane; distant points don't affect it.

Soft Margin Hyperparameter (C)

  • Large C: Narrower street, penalizes misclassifications heavily (risks overfitting).
  • Small C: Wider street, allows some margin violations for better generalization.
SUPERVISED: CLASSIFICATION12 / 22

SVM: The Kernel Trick (Non-Linear Boundaries)

Implicitly projecting inseparable 2D data into higher dimensions without computing coordinates.

Further Visuals & Docs: StatQuest: SVMs Playlist Classifier Comparison

How Kernels Work

  • The Problem: Concentric rings or spirals cannot be separated by a straight line in 2D.
  • Kernel Trick: K(x, x') computes dot products in a higher-dimensional space (e.g., RBF Gaussian kernel).

Key Hyperparameters & Trade-offs

  • Gamma (RBF): Controls how far a single point's influence reaches (high gamma = tight islands).
  • Scalability: Great on small/medium datasets; slow O(n^2–n^3) on hundreds of thousands of rows.
TREE-BASED MODELS13 / 22

Decision Trees (CART): How Splits Work

Greedy recursive binary splitting that maximizes node purity at every branch.

Further Visuals & Docs: R2D3: Visual Intro to ML StatQuest: CART Playlist

Architecture & Split Criteria

  • Node Anatomy: Root node -> internal decision nodes (x_j <= t) -> leaf predictions.
  • Impurity Metrics: Gini Impurity (1 - sum(p_k^2)) or Entropy for classification; MSE for regression.

Strengths & Properties

  • Scale Invariant: No feature scaling needed; handles mixed numeric/categorical features and non-linear interactions.
  • White-Box Model: Easy to visualize and explain every decision path step-by-step.
TREE-BASED MODELS14 / 22

Decision Trees: Pruning & Controlling Overfitting

Why single unconstrained trees overfit and how structural constraints fix them.

Further Visuals & Docs: R2D3: Visual Intro to ML

Pre-Pruning & Post-Pruning

  • Unconstrained Risk: A full tree creates 1-sample leaves that memorize every outlier in training data.
  • Pre-Pruning: Limit max_depth, min_samples_split, or min_samples_leaf before growth stops.

Why Ensembles Come Next

  • Cost-Complexity Pruning: Trim weak branches post-training using ccp_alpha.
  • High Variance: Even pruned single trees are sensitive to small data changes — ensembles solve this!
ENSEMBLE MODELS15 / 22

Random Forests (Bagging + Feature Subsampling)

Averaging hundreds of decorrelated decision trees to slash variance.

Further Visuals & Docs: StatQuest: Random Forests Kaggle Intro to ML

Why Random Forests Work

  • Bootstrap Aggregation: Each tree trains on a random sample with replacement (~63% unique rows).
  • Feature Subsampling: Each split tests only sqrt(M) random features, preventing one strong feature from dominating.

Practical Advantages

  • Out-of-Bag (OOB): Unused ~37% rows act as a built-in validation check.
  • Strong Baseline: Usually saturates as trees are added and handles tabular data with minimal tuning, though noisy data can still overfit.
ENSEMBLE MODELS16 / 22

Gradient Boosted Decision Trees (GBDT)

Sequential additive training where each shallow tree fits the prior model's residuals.

Further Visuals & Docs: StatQuest: Gradient Boost

Additive Residual Architecture

  • Sequential Correction: F_m(x) = F_(m-1)(x) + lr * h_m(x). Unlike Random Forests, trees are NOT independent.
  • Weak Learners: Uses shallow trees (depth 3–6) that progressively reduce bias.

Key Hyperparameters

  • Learning Rate (lr): Small lr (0.01–0.1) shrinks each tree's step for better generalization.
  • Early Stopping: Stop adding trees when validation error stops improving to prevent overfitting.
ENSEMBLE MODELS17 / 22

XGBoost, LightGBM & CatBoost

Production-grade GBDT libraries dominating tabular benchmarks and Kaggle competitions.

Further Visuals & Docs: XGBoost Docs Kaggle Competitions

Architectural Differences

  • XGBoost: Level-wise tree growth, 2nd-order Taylor gradients (Hessian), built-in L1/L2 leaf regularization.
  • LightGBM: Histogram binning + leaf-wise growth (splits highest-gain leaf first -> super fast on large data).

Choosing a GBDT Library

  • CatBoost: Oblivious/symmetric trees + ordered target encoding for native categorical columns.
  • Rule of Thumb: LightGBM for speed/scale, CatBoost for heavy categoricals, XGBoost as the classic all-rounder.
UNSUPERVISED: CLUSTERING18 / 22

K-Means Clustering

Iterative centroid-based partitioning minimizing within-cluster sum of squares (inertia).

Further Visuals & Docs: Naftali Harris: K-Means

Iterative Centroid Algorithm

  • Init & Assign: Initialize K centroids (k-means++) and assign every point to its nearest centroid.
  • Update & Converge: Recompute each centroid as the cluster mean; repeat until assignments stop changing.

Choosing K & Limitations

  • Elbow Method: Plot Inertia vs. K (or Silhouette Score) to find where diminishing returns start.
  • Limitation: Assumes spherical, equally sized clusters and is sensitive to outliers and feature scale.
UNSUPERVISED: CLUSTERING19 / 22

DBSCAN Clustering

Density-based clustering that discovers arbitrary shapes and flags outliers automatically.

Further Visuals & Docs: Naftali Harris: DBSCAN Sklearn Clustering Demo

Core, Border & Noise Points

  • Core Point: Has at least min_samples neighbors within radius eps.
  • Density-Reachable: Chains core points together — effortlessly traces moons, rings, and irregular shapes.

Strengths & Limitations

  • Outlier Detection: Isolated points in sparse regions are labeled -1 (Noise) instead of forced into clusters.
  • Limitation: Struggles when clusters have widely varying densities (use HDBSCAN for that).
UNSUPERVISED: COMPRESSION20 / 22

Principal Component Analysis (PCA)

Orthogonal linear projection onto principal axes that maximize retained variance.

Further Visuals & Docs: Setosa.io PCA Visual StatQuest: PCA Step-by-Step

Architecture & Math Intuition

  • Eigenvectors / SVD: Finds perpendicular axes (PC1, PC2, ...) ordered by how much variance they explain.
  • Projection: Z = X * W compresses correlated features into uncorrelated components.

Best Practices & Use Cases

  • Scaling Required: Always standardize features first so large-scale columns don't hijack PC1.
  • Use Cases: 2D/3D visualization, noise filtering, and speeding up downstream models (keep ~95% variance).

Model Selection Cheat Sheet

Matching problem structure, data size, and interpretability requirements.

Linear / Polynomial + Ridge / Lasso — Continuous target, linear/smooth relationships, interpretability Key Hyperparameters: alpha, degree
Logistic Regression / Naive Bayes / SVM — Binary or multiclass classification; text (NB) or non-linear margins (RBF SVM) Key Hyperparameters: C, kernel, gamma
Decision Trees & Random Forests — Tabular data with mixed feature scales & non-linear interactions Key Hyperparameters: max_depth, n_estimators
XGBoost / LightGBM / CatBoost — State-of-the-art performance on structured/tabular datasets Key Hyperparameters: learning_rate, max_depth
K-Means / DBSCAN / PCA — Unlabeled clustering (blobs vs. arbitrary shapes) or dimensionality reduction Key Hyperparameters: n_clusters, eps, n_components
